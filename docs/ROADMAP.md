## Phaseを進めるルール

1. 原則、Phase 2の残課題を優先し、完了条件を満たしたらPhase 3～5の検証を進める。
2. Phase 0/1/3/4は実装が存在するが、**検証が終わるまでは「完了」にしない**。
3. Phase 5の品質確認は各Phaseと並行して進めてよい。
4. 各開発セッション終了時に `docs/HANDOVER.md` に現在のPhase、完了作業、残課題、次の一手を記録する。
5. Phaseの範囲・完了条件を変更したら本書と必要に応じて `docs/SPECIFICATION.md` を更新する。
6. GitHub Actionsは手動実行のみ。追加課金やPublic化を伴う操作は事前承認が必要。
